# Chess Review

A self-hosted chess analysis app that doesn't just tell you a move was a mistake — it explains **why**, in plain English, the way a coach would.

Most analysis tools paste an engine evaluation next to your move (`-2.4`, "Blunder") and leave you to figure out the rest. Chess Review pairs a Stockfish backend with a deterministic, template-driven explanation engine that turns raw engine output into sentences like *"This drops the pawn because after ...Qxd4 the rook on a1 is undefended"* — and a human-move model (Maia-2) that tells you whether players at your level actually find the better move.

> Built as a personal coaching tool for a ~1100-rated club player. The design goal throughout: **an explanation line, read on its own, should never feel dumb or wrong.**

---

## Why it's interesting (engineering highlights)

- **No-LLM explanation engine.** Move explanations are generated by a pipeline of deterministic *detectors* and *templates*, not a language model. Every claim ("the knight is now undefended", "this trades into a winning rook endgame") is derived from the board state and verified by an **auditor** that rejects unsupported sentences — measured at **0 false claims across 313 test positions**. This makes the output fast, free, reproducible, and unit-testable.
- **Stockfish process pool.** Game analysis runs across a pool of independent Stockfish 18 (NNUE) workers at lower OS priority, so a full game analyzes in the background without freezing the UI. Tuned empirically — for fixed-depth search, `Threads=1` per worker beats SMP, with parallelism coming from analyzing many positions at once.
- **Human-move probabilities (Maia-2).** Integrates the CSSLab Maia-2 model to answer *"would a player my rating actually have found this?"* — e.g. *"75% of players at your level would play this too"* vs *"almost nobody finds Kh5."* The app degrades gracefully and runs fully without it.
- **Contrastive, depth-aware analysis.** Explanations compare the move played against the engine's top lines (multi-PV), surface the concrete refutation, and recognize positional and endgame themes (ladders, color complexes, king mobility, endgame transitions).
- **Openings trainer with spaced repetition.** Build a repertoire, drill saved lines on an SM-2-style schedule, and get trap warnings backed by the explorer + engine.
- **Play vs. a human-like bot.** Play against a Maia-sampled or skill-limited opponent with live, ~1–3s coaching as you move.

## Tech stack

**Backend** — Python · FastAPI · python-chess · Stockfish 18 (NNUE) · Maia-2 (PyTorch) · SQLite
**Frontend** — React 19 · Vite · Chessground · chess.js · React Router
**Testing** — pytest (110+ tests, including a golden-position regression suite and a claim auditor)

~22k lines of Python across the analysis pipeline, plus a React SPA.

## Architecture

```
                 ┌──────────────────────────────────────────────┐
   Browser  ◄───►│  FastAPI (backend/main.py)                   │
   React SPA     │   • game import (Chess.com / PGN)             │
                 │   • analysis jobs (SSE progress)             │
                 │   • openings / repertoire / play endpoints   │
                 └───────────────┬──────────────────────────────┘
                                 │
         ┌───────────────────────┼───────────────────────────┐
         ▼                       ▼                           ▼
  Stockfish pool          Explanation engine            Maia-2 model
  (depth 20 / 24,         detectors → templates →       P(move | rating)
   multi-PV, NNUE)        auditor → rendered text       human-move facts
         │                       │
         ▼                       ▼
                      SQLite (games, moments, explanations)
```

| Layer | Where |
|-------|-------|
| API & job orchestration | `backend/main.py`, `backend/analyzer.py` |
| Engine integration | `backend/stockfish_engine.py`, `backend/engine_lines.py` |
| Explanation pipeline | `backend/explanation_*`, `backend/clean_explanations.py`, `detectors/`, `explanations/` |
| Positional / endgame concepts | `evaluators/`, `backend/chess_endgame.py`, `backend/chess_positional.py` |
| Human-move model | `backend/maia_facts.py`, `maia2_models/` |
| Openings & repertoire | `backend/openings.py`, `backend/opening_tree.py`, `backend/repertoire.py` |
| Play vs. bot | `backend/play_coach.py`, `backend/game_runner.py` |
| Frontend SPA | `frontend/src/` |

## Getting started

### Prerequisites

- Python 3.10+
- Node.js 18+
- [Stockfish](https://stockfishchess.org/) (`brew install stockfish` on macOS)

### Setup

```bash
# 1. Backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 2. Frontend
cd frontend && npm install && cd ..

# 3. Config
cp .env.example .env
# edit STOCKFISH_PATH if Stockfish isn't at /opt/homebrew/bin/stockfish
```

The Maia-2 model (~267 MB) downloads automatically into `maia2_models/` on first run. To skip it, set `MAIA_ENABLED=false` in `.env`.

### Run

```bash
./start.sh            # production: builds the frontend, serves on http://localhost:8000
./start.sh --dev      # dev: Vite HMR on :5173 + uvicorn on :8000
```

Then open the URL it prints, import a game (Chess.com username or PGN), and review.

### Tests

```bash
source venv/bin/activate
pytest
```

## Configuration

All tuning lives in `.env` (see `.env.example` for the full annotated list):

| Variable | Purpose |
|----------|---------|
| `STOCKFISH_PATH` | Path to the Stockfish binary |
| `ANALYSIS_DEPTH` / `ANALYSIS_DEPTH_CRITICAL` | Search depth for normal vs. critical moments |
| `STOCKFISH_POOL_WORKERS` | Parallel analysis workers |
| `BLUNDER_THRESHOLD` | Centipawn-loss cutoff for flagging mistakes |
| `MAIA_ENABLED` / `MAIA_ELO` | Toggle the human-move model and set its rating |

## Notes

- Local databases, the Maia model weights, and build artifacts are git-ignored — they're regenerated/downloaded locally rather than committed.
- The explanation engine is intentionally **LLM-free**: deterministic, auditable, and covered by tests, so output quality can be measured rather than vibed.
